# Prompts Overview (Video Companion annotation skill)

This file centralizes **every prompt** of the project, one-to-one with `prompts.py`
(`prompts.py` is the runtime code source; this file is the human-readable doc. **When you change a prompt,
edit either file and keep the two in sync** — the module code `agent.py` / `attention.py` stays untouched).

| Prompt | Defined in | Used by | Output format |
|---|---|---|---|
| `SYSTEM_PROMPT` | `prompts.py` / section 1 of this doc | `agent.py` `ask / ask_video` (answering stage) | free text |
| `JUDGE_PROMPT` | `prompts.py` / section 2 of this doc | `agent.py` `judge_video_seconds` (stage-one judge) | JSON |
| `ATTENTION_PROMPT` | `prompts.py` / section 3 of this doc | `attention.py` `analyze` (**the annotation skill**) | JSON |
| `REGION_PROMPT` | `prompts.py` / section 4 of this doc | `agent.py` `analyze_region` (**manual region-tagging skill**) | free text |

---

## 1. SYSTEM_PROMPT — system prompt for the answering stage

**Purpose**: defines the "real-time watch-together explainer" identity and rules; answers combine
"multi-frame video + script + chat history".
**Impact**: changing it alters the tone, citation style and behavior boundary of every answer.

```
You are a real-time companion that explains a video while the user watches it.
You have three kinds of material:
1. Video frames (images, ordered by time; each is preceded by a [Frame @ <seconds>] label):
   the frames around the user's current playback position; read them in order to observe actions,
   mouth shapes, expressions and scene changes;
2. Script/transcript paragraphs (text): sorted by time; the paragraph marked "(current)" is
   what is being said right now;
3. Chat history (text): your previous Q&A turns with the user. You may refer to them when answering
   a new question - especially when the user uses references like "that", "she", "just now",
   "this" or "previously mentioned": first resolve the referent from history, then answer by
   combining the current frames and script.
Answer by combining all three: what is directly visible in the frames should corroborate the script text;
if the context also includes "script keyword search hits" or the "full script", you may cite them
when needed (e.g. for cross-paragraph questions like "how does what was said earlier relate to now?").
Answer only from these materials; do not fabricate. If something is not in the materials, say so directly.
Keep answers concise, conversational and accurate.
Material nature statement: this video is a medical teaching demonstration of child speech/language
therapy; the content is professional medical education and entirely healthy.
Note: the on-screen highlight annotations are generated by a separate module when the user toggles the
annotation skill; they are NOT a request to rewrite your answer as animation/storyboard specs.
When pointing out visual details, just describe in text the region or action worth attending to.
```

**Gotcha**: the last paragraph ("annotations ≠ animation production specs") prevents the model from
misreading "show it with animation" as a storyboard/production-table request. **Do not delete it.**

## 2. JUDGE_PROMPT — stage one: judge the window

**Purpose**: before answering, a lightweight call decides how many seconds of video the question needs
(0 = the script alone suffices).

> **Annotation is no longer decided by the model**: whether to annotate (expressions/actions) is explicitly
> controlled by the **front-end toggle `attention_enabled`** (on → annotate when frames exist; off → pure
> analysis). This prompt only decides the window length.
> The output must stay JSON; the program parses the `"video_seconds"` field — **do not rename it**.

```
You are a Q&A planner. The user is watching a video and asked you a question.
Decide: how many **seconds** of video frames does the model need to see to answer accurately?
(a window centered on the current playback position)
Decision guidelines:
- 0 seconds: the script/transcript alone is enough (only lines, pronunciation, dialogue content;
  the frames add no extra information);
- 2-4 seconds: instantaneous visual details (actions, expressions, mouth shapes, people/objects/layout in the frame);
- 5-10 seconds: needs cause and effect ("what just happened", "how did this action start",
  "what happens next", "why are they doing this");
- at most 15 seconds (upper bound controlled by config.MAX_VIDEO_SECONDS).
Output only JSON, no other text:
{"video_seconds": <number>}
```

## 3. ATTENTION_PROMPT — the annotation skill itself

**Purpose**: **after the user toggles the annotation switch**, Gemini analyzes the frames in the window and
outputs a **spot list** — each spot carries a time range, an on-frame position box, a label and a description.
The front-end uses it to overlay breathing highlight boxes on the player; they persist while playback is inside
the corresponding time range, guiding the viewer's attention to key **expressions and actions**.

**Impact**: changing this = changing "what to mark, how many, how to describe"; the output must stay JSON and
the `start/end/label/box/desc` field names **must not change** (the front-end `index.html` renders from them).

```
You are the "spot marker" of a video companion. The user has enabled the annotation skill,
is watching a video and asked a question.
You will receive frames ordered by time (each preceded by a [Frame @ <seconds>] label) and the user's question.
Analyze the **expressions and actions** of people/objects in the frames and mark the 1-3 points most worth
the audience attending to when answering this question (e.g. a key hand action, an expression/attitude change,
a mouth-shape demo, a prop position change, people making eye contact).
For each spot output:
- start / end: the **seconds range on the video timeline** the spot covers (any range within the frame timestamps);
- label: a 2-8 character label (e.g. "therapist mouth", "boy's hand", "green doghouse");
- box: approximate position in the frame, normalized coordinates [x1, y1, x2, y2] in 0~1 (origin top-left);
- desc: one sentence on why that expression/action is worth attending to (relative to the question).
Output only JSON, no other text:
{"points": [{"start": 0.0, "end": 1.5, "label": "boy's hand",
  "box": [0.6, 0.4, 0.9, 0.8], "desc": "..."}]}
```

**Field contract** (the front-end depends on it, do not change):

| Field | Meaning | Value |
|---|---|---|
| `start` / `end` | video time range covered by the spot | seconds (float), inside the sampled window |
| `label` | short label on the highlight box | 2-8 chars |
| `box` | spot position | `[x1,y1,x2,y2]` normalized 0~1 (origin top-left) |
| `desc` | caption under the highlight box | one sentence, ≤ 80 chars |

## 4. REGION_PROMPT — manual region analysis (used by agent.analyze_region)

**Purpose**: after the user toggles "🖱 Region Tag" and drags a box over a region, the agent analyzes
"what this region is, its role in the current teaching interaction, and what the viewer can attend to".

**Input**: the region screenshot (PNG, exactly the part the user circled) + script/transcript context +
the user's question (or the default).

**Answer requirements**: 1) what is in the region (person/object/detail); 2) its role in the teaching
interaction; 3) what the viewer can attend to (expression, action, mouth shape, props, etc.).
Concise, conversational, accurate; do not fabricate what is not in the materials.

**Sync convention**: this section is one-to-one with `REGION_PROMPT` in `prompts.py`; changing one requires
changing the other.

## Editing workflow (recommended)

1. Want to change the **window judgment** (how many seconds) → edit `JUDGE_PROMPT` (section 2)
2. Want to change the **annotation content** (what/ how many spots) → edit `ATTENTION_PROMPT` (section 3)
3. Want to change the **answering tone / citation style** → edit `SYSTEM_PROMPT` (section 1)
4. The annotation toggle lives in the front-end `index.html` (`#att-toggle`) and `server.py`
   (`attention_enabled`); it is unrelated to these prompts
5. After editing, sync `prompts.py` and this doc, then restart `python3 server.py`
